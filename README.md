# BlockMade

LEGO風のブロックで設計した作品を3Dで確認できるビューアです。完成形、組み立て手順、パーツ一覧、構造チェックを見られます。作品をライブラリとしてストックでき、AIに新しい作品を設計させることもできます。

## 作品ライブラリ

作品は `models/` に1作品1ファイルのJSONとして保存します。一覧は `models/index.json` です。

東京スカイツリーは 1スタッド＝2m の縮尺で、高さ634mを約793プレート分で再現した大型作品です。`tools/gen-tokyo-skytree.mjs` が形状（足もとの正三角形が320mで円になる断面、X形トラスと水平リング、心柱、天望デッキ、らせん状の天望回廊、ゲイン塔）から部品を割り付けて生成します。形を調整したら `node tools/gen-tokyo-skytree.mjs` を実行してから、下の2つのコマンドを実行します。

シドニー・オペラハウスは 1スタッド＝1.25m・1プレート＝0.5m の縮尺で、ベネロング岬とまわりの湾まで含めた 144×212 スタッドの大型作品です。`tools/gen-sydney-opera-house.mjs` が、ウッツォンの「球面解法」にならってシェルを球面から切り出した形（左右の半シェルが鏡像になったとがったアーチ、脚を軸にした扇形の輪郭）を幾何計算し、ボクセルに分けてから実在の部品に割り付けます。シェルの表面は白とクリームのタイル、口と重なりのすき間はブロンズの桟が入ったトパーズ色のガラス、足もとは花崗岩の基壇と大階段、ブロードウォーク、王立植物園の崖、湾を行くフェリーです。レイヤー表示で切ると、コンサートホールとジョーン・サザーランド劇場の客席・舞台・パイプオルガン・フライタワーも見えます。形を調整したら `node tools/gen-sydney-opera-house.mjs` を実行してから、下の2つのコマンドを実行します。

東京駅 丸の内駅舎は 1スタッド＝2m・1プレート＝0.8m の縮尺で、全長約335mの駅舎を168スタッドで再現し、丸の内駅前広場と行幸通り、奥のホームと電車まで含めた 184×112 スタッドの作品です。`tools/gen-tokyo-station.mjs` が、翼部・4つの塔屋・中央部・南北の八角ドームをそれぞれ「ボリューム」として扱い、2スタッド厚の壁に辰野式のリズム（赤れんが、白い石の帯、1スタッド奥にはめた窓、塔屋の角の隅石）を割り付けます。屋根は3プレートずつ内側へ寄せる寄棟で、段差がちょうど1段分になった列を自動でスロープに置き換えます。ドームは楕円断面で立ち上げて頂塔と頂部飾りを載せ、南北口と中央の車寄せにはアーチを架けます。形を調整したら `node tools/gen-tokyo-station.mjs` を実行してから、下の2つのコマンドを実行します。

清水寺は 1スタッド＝1.5m・1プレート＝0.6m（実物のブロックと同じ比率）の縮尺で、紅葉の盛りの音羽山を 136×96 スタッドで再現した作品です。`tools/gen-kiyomizu-dera.mjs` が、清水坂の石段・仁王門の段・境内の台地・崖・錦雲渓の谷を高さの場として作り、ブロック1段（3プレート）ごとの段々に整えます。本堂と奥の院は懸造で、3スタッドおきの格子に礎石と丸ブロックの柱を立て、7プレートごとに貫を渡します（縦横の貫は1プレートずらして柱で交差させます）。屋根は寄棟・入母屋・切妻を1つの関数で扱い、軒先は奥行き4のスロープ、棟に向かって奥行き3・2のスロープと段ごとに急にして、社寺の反りのある屋根の勾配を出します。朱塗りの堂塔は丹塗りの柱に白壁と緑の連子窓、軒下に黄色い垂木先の線を吊ります。地形の中は本物のブロック作品と同じく空洞にし、8スタッドおきの2スタッド幅の壁で支え、土台の8×8プレートはどれもその壁の下に来るようにしています。形を調整したら `node tools/gen-kiyomizu-dera.mjs` を実行してから、下の2つのコマンドを実行します。

サグラダ・ファミリアは、完成後の姿を 1スタッド＝2m・1プレート＝0.8m の縮尺で再現した作品です。高さ172.5mのイエス・キリストの塔は十字架まで216プレート、アシャンプラ地区の角を切った街区（約120m四方）が60スタッドで、まわりの通りと広場を含めて 88×88 スタッドです。`tools/gen-sagrada-familia.mjs` は、建物をまず「中身の詰まった立体」として描きます。ラテン十字の平面（5廊式の身廊、3廊式の翼廊、7つの礼拝堂が並ぶ後陣）、18本の塔をガウディの放物線の輪郭をもつ回転体、3つのファサードの門を急な破風の下の放物線アーチとして置き、そのあと26近傍がすべて埋まったボクセルを取り除いて、壁も塔も1スタッド厚の殻にします。塔が細くなる段では、殻が自動で下の段の上に棚を残すので、上の段は必ず何かに載ります。交差部の4本の柱（福音書記者の塔の足もと）とヴォールトの天井は、くり抜かずに残します。そのうえで、ステンドグラス（東の生誕側は青と緑、西の受難側は赤と橙）、鐘楼のらせん状の開口、ベネチアンガラスのモザイクの尖塔、45°スロープの急な切妻屋根と2×4スロープの片流れ屋根、受難のファサードの傾いた柱と骨の破風、栄光のファサードの柱とランタン、果物のかごの尖塔、タクシーと観光バスを加え、清水寺と同じ方法で各プレート段を実在の部品に割り付けます。形を調整したら `node tools/gen-sagrada-familia.mjs` を実行してから、下の2つのコマンドを実行します。

### 作品の追加方法

- **Claude とのチャットで追加する**: 「〇〇を追加して」と頼むと、Claude が設計して `models/` に保存し、構造チェックを通します。
- **アプリの「✦ AIで作る」から作る**: 作りたいものを入力すると、アプリ内で Claude が設計します。構造チェックで問題が見つかった場合は、最大2回まで AI に修正させ、それでも残れば自動で修復します。できた作品はそのブラウザに下書きとして保存され、Step 1 から組み上げて見せます。
  ライブラリに登録するには、ライブラリ画面のカードで「登録用にコピー」を押し、その内容を Claude とのチャットに貼り付けてください。
- **手で追加する**: JSON を `models/` に置き、`node tools/validate.mjs` と `node tools/build.mjs` を実行します。

## 起動方法

`index.html` をブラウザで開くだけで動きます。共通コードと全作品を埋め込んだ、単一ファイルのページです。

作品やコードを変更したら、次の2つを実行します。

```sh
node tools/validate.mjs   # 全作品を検証し、models/index.json を更新
node tools/build.mjs      # index.html と dist/artifact.html を生成
```

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `blockmade.html` | アプリ本体のソースです。`js/model-core.js` と `models/` を参照します |
| `index.html` | ビルド済みのスタンドアロン版です（コードと作品を埋め込み済み） |
| `dist/artifact.html` | claude.ai の Artifact として公開するページです（ビルドで生成し、コミットしません） |
| `js/model-core.js` | モデルの正規化・構造チェック・自動修復・JSON変換を行います。ブラウザとCLIで共用します |
| `models/*.json` | 作品データです |
| `tools/validate.mjs` | 全作品を検証し、`models/index.json` を再生成します |
| `tools/build.mjs` | Three.js・共通コード・全作品を埋め込み、単一ファイルのページを生成します |
| `tools/gen-tokyo-skytree.mjs` | 東京スカイツリー（`models/tokyo-skytree.json`）を生成します |
| `tools/gen-sydney-opera-house.mjs` | シドニー・オペラハウス（`models/sydney-opera-house.json`）を生成します |
| `tools/gen-tokyo-station.mjs` | 東京駅 丸の内駅舎（`models/tokyo-station.json`）を生成します |
| `tools/gen-kiyomizu-dera.mjs` | 清水寺（`models/kiyomizu-dera.json`）を生成します |
| `tools/gen-sagrada-familia.mjs` | サグラダ・ファミリア（`models/sagrada-familia.json`）を生成します |
| `vendor/` | Three.js r147 と OrbitControls（MIT License）です |

1200個以上の部品をもつ作品は、ビューアが自動で「まとめ描画」に切り替えます。同じ Step・同じ高さ・同じ質感の部品を1つのメッシュにまとめ、ほかの部品に隠れるスタッドは描きません。1万個を超える作品でも、組み立てモード・レイヤー表示・分解表示・部品のクリック選択はそのまま使えます。構造チェックはスタッドの列ごとに部品を索引してから接触を調べるので、4万個を超える作品でも一瞬で終わります。

公開するページには、Three.js（`vendor/`、MIT）を含めて必要なスクリプトをすべて埋め込み、外部からスクリプトを一切読み込まないようにしています。Artifact のビューアでは、外部スクリプトの読み込みが失敗することがあるためです。

## モデル形式（version 2）

```js
{ id: "block_001", shape: "slope", type: "slope-2x2", width: 2, depth: 2, height: 3,
  x: 0, y: 6, z: 0, rotation: 180, color: "red", step: 4 }
```

- **単位**: x・z はスタッド、y・height は **プレート**（ブロック1個 = 3プレート）です。version 1 のファイル（y・height がブロック段数）は、読み込むときに自動で変換します。
- `x, y, z` は部品の最小角を表します。
- `rotation`（0 / 90 / 180 / 270）は、部品の奥行き方向（スロープが下っていく向き）を表します。0 = +Z（正面）、90 = +X、180 = −Z、270 = −X です。0・180 のときは width が X 方向、90・270 のときは depth が X 方向になります。
- `shape` を省略すると `brick` として扱います。使える部品は下の表のとおりです（実在のサイズは `js/model-core.js` の `PARTS` にまとめています）。

| shape | 部品 | 高さ | 上面のスタッド | 下で受ける位置 |
| --- | --- | --- | --- | --- |
| `brick` | ブロック | 3（6 = 2倍の高さ） | 全面 | 全面 |
| `plate` | プレート | 1 | 全面 | 全面 |
| `tile` | タイル | 1 | なし | 全面 |
| `slope` | スロープ 45° | 3 | 奥の1列だけ | 全面 |
| `slope-inv` | 逆スロープ | 3 | 全面 | 奥の1列だけ |
| `round-brick` / `round-plate` / `round-tile` | 丸ブロック・丸プレート・丸タイル | 3 / 1 / 1 | 全面 / 全面 / なし | 全面 |
| `cone` | コーン | 3（2×2 は 6） | なし | 全面 |
| `arch` | アーチ | 3 | 全面 | 両端だけ |

- `colors` で色を定義します。`js/model-core.js` の標準色（`red`, `trans-blue` など）は、`colors` に書かなくても使えます。
- 任意の `print: { pattern: "clock", face: "+z" }` を付けると、ブロックの指定した面に時計の文字盤が描かれます。

## 構造チェックのルール

- **Connected**: スタッドでつながるブロックが、すべて1つの構造体にまとまっているか。
- **Supported**: すべてのブロックが、接続をたどって地面（y = 0）まで届くか。
- **No collisions**: 同じ空間を複数のブロックが占有していないか。
- **Build order valid**: 各 Step で追加するブロックが、その時点で地面か配置済みのブロックに取り付けられ、上下の既存ブロックに挟まれていないか。

上の部品がちょうど下の部品の上面に載っていて、下の部品のスタッドが上の部品の受ける位置に1つ以上はまっているときだけ「接続」とみなします。そのため、タイルやコーンの上、スロープの斜面の上には何もつながりません。アーチは両端だけで支えます。横に並んでいるだけでは接続になりません。
